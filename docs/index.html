qingsong 青松 documentation

qingsong keeps a project's requirements as checked, versioned engineering records in a git repository, and generates the documents people read from them. Version 0.2.0.dev0.

New here? Read the Overview, then How to use qingsong. Agents also follow the contributor rules; every command accepts --json.

The workflow at a glance

  1. 1. BranchNever on main: every change starts on a branch.
  2. 2. EditChange the record's YAML file, or create one with qingsong new.
  3. 3. Recordqingsong revise stamps it and adds a history event.
  4. 4. Checkqingsong check: no errors before a commit.
  5. 5. ReviewIssues, proposed fixes and the review page's decisions file.
  6. 6. ApproveAn approver approves; merges happen with their permission.
  7. 7. Releaserelease prepare, merge, release tag, issued copy.

Each step is explained, with examples, in How to use qingsong.
