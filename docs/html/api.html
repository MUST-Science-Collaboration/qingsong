API reference

This is the reference for people and agents who change qingsong itself. To use qingsong on a project's requirements, read How to use qingsong; for the design and its reasons, read the specification.

The first part, written by hand, explains how the code is organised, what every change must preserve, and how to extend it. The second part is generated from the code by tools/build_docs.py: every command, every check rule, and every module with its classes and functions. Do not edit the second part; change the docstrings and rebuild.

How the code is organised

The package lives in src/qingsong/. It has four layers. Each layer uses only the ones before it, and the command line sits on top.

Layer Modules What it does
Records and the vault schema, vault, ids, hashing, findings, walk Pydantic models of every record type; strict loading of a vault into memory; ID syntax and file paths; stamps and text hashes; the Finding a check reports
Checks checks and its six rule modules Rules that read a loaded vault and report findings. They never write.
Changing the record operations, review, decisions_file, slots, wording, release, gitutil Every change to a record file, each one recorded: new records, revisions, approvals, lifecycle changes, issues and proposals, decisions files, slot moves, releases. gitutil reads earlier states through git.
Outputs render.model, render.text, render.html, render.word, export The HTML site, Word documents and the JSON export, all generated from a loaded vault
Command line cli Typer commands. Each one parses its options, calls one function of the layers above, and prints text or JSON.

A command, end to end. qingsong revise ID --class value --summary S --by P:

  1. cli.revise finds the vault root and calls operations.revise.
  2. operations.revise loads the vault (vault.load) and checks the request. For example, it refuses editorial when the values changed.
  3. It edits the record's YAML through operations.edit. That reads the file with comments kept, applies the change, and passes it to finish.
  4. finish validates the result against the schema, writes the normative hash and the stamp, writes the file atomically, and reads it back to check that the stamp holds.
  5. The command prints the new revision, or a JSON object with --json.

qingsong check is the read side: vault.load collects load findings, checks.run runs every rule, and issues that track a rule's findings are attached to them.

What every change must preserve

These invariants are what make the record trustworthy. Tests guard each of them.

  • Strict reading. Unknown fields, unreadable files and missing references are errors. Nothing is filled in by default when a file is read (schema.StrictModel forbids extra fields).
  • Every write is recorded. Record files change only through operations (edit, finish, write_atomically). Each change bumps revision, appends to history and rewrites stamp. A hand edit without a recorded event fails change.unrecorded.
  • History is append-only, and identity is permanent. An ID never changes once it is on the main branch. A record is superseded or withdrawn, never deleted. integrity.against compares with an earlier state to enforce this.
  • Files keep their form. YAML is read and written with ruamel.yaml in round-trip mode, so comments, key order and literal blocks survive an edit.
  • Refusals name the fix. An operation that cannot proceed raises OperationError with a message that says what to do. The command line prints it and exits with status 2, or prints {"error": …} with --json. qingsong check exits with status 1 when any error is found.
  • No hidden state. The vault root is passed explicitly, or found from the working directory by vault.find_root. Nothing writes environment variables or global caches.
  • Dates are parameters. Every operation takes today. Tests pass a fixed date to every call in a test. History dates must not go backwards (change.history), so mixing a fixed date with the real date fails on another day.
  • New schema fields default to None. The stamp covers every field that is not None. A new field with any other default, such as an empty list, would change the stamp of every existing record.

Extending qingsong

A new check rule.

  1. Choose the group module in src/qingsong/checks/: integrity, structure, change, content, consistency or documents.
  2. Write a function that takes a checks.Context and yields Finding(rule, severity, message, record, file, fix). Register it with @rule("group.name", "one-line summary"). Use checks.by_maturity when the severity depends on the requirement's maturity.
  3. Add a fixture to tests/test_rules.py that triggers the rule. Every rule must have one.
  4. Add the rule to the catalogue in the specification, then rebuild the docs so that it appears in the rule list below.

A new record type.

  1. Add a model to schema.py, with type: Literal["…"], deriving from RecordBase.
  2. Add it to Record, record_classes and record_folders (its folder). Add its ID pattern to ids.id_patterns.
  3. Add its fields' references to walk.py, so that reference checks and renumbering see them.
  4. Describe it in the specification (§5.3), and add the checks and fixtures it needs.

A new command.

  1. Add a Typer function to cli.py. Use the shared options VaultOption, JsonOption, PersonOption and ViaOption.
  2. Call one function of the layers above. Catch OperationError and pass it to fail. Print with emit, or with done for a single record.
  3. The function's docstring becomes the command's help and its entry in the command list below. Add the command to the specification (§11), and to How to use qingsong if people or agents use it day to day.

Tests. uv run pytest. Tests build the fictional DEMO vault from examples/demo_source with examples/build_demo.py, through the fixtures demo (a folder) and demo_repository (a git repository with its own git identity). They never touch a real vault.

Documentation. After changing a docstring, a command, a rule or any Markdown document, run uv run python tools/build_docs.py. tests/test_docs.py fails while the generated files are out of date.
